# A calibration names a report that is in the repository

A `calibration` document MUST carry a `report:` key, and the path it names
MUST resolve to a file that exists, relative to the vault root.

The document carries three coefficients and a verdict. None of the three
is interpretable on its own: a kappa is a function of the marginals as
well as of the agreement, so the same coefficient means different things
under different distributions of answers, and reading one without its
`p_o`, its `p_e`, its two marginal vectors, its interval and its sample
size is reading a number that cannot be checked. Those live in the report,
along with the per-item journal that says which items the judge and the
people disagreed about. A calibration whose report is missing is a verdict
with its evidence deleted.

The report is therefore committed rather than left on whichever machine
ran the judge. It holds aggregate counts and paths relative to the suite,
so there is nothing in it that cannot be published — unlike a verifier
health check's report, which is the verifier's own output, carries the
absolute paths of the host that produced it, and is deliberately not kept.
That difference is why this clause is about calibrations and not about
every record that names a report.
