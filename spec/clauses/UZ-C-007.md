# A pull request carries one roadmap step

A pull request against a repository this standard governs MUST correspond
to exactly one roadmap step. A step is claimed by a marker in the pull
request's title or body, read case-insensitively as `\bstep[ \t]+(\d+)\b`
— which is how `Step 6` and `roadmap step 6` are one spelling, and why a
marker never spans a line break, spaces and tabs being the only run
between the word and its number.

Two distinct numbers in one pull request is a violation; the same number
written many times is one claim. A number outside 1 to 7 is a violation
too: it names a step the roadmap does not have, and reading it as no
claim at all would let a typo buy silence.

A pull request with no marker is allowed and is reported as unlabelled.
The rule bounds what a change may claim, not whether it claims anything:
an unlabelled change is read on its diff, which is the ordinary case,
while a change claiming two steps has asked to be read on two arguments
at once.

Scope, in the failure this cites, was a rule about the shape of an
artefact and never about its amount. This is the amount.
