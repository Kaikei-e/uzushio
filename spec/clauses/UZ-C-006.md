# Test code is capped against the code it tests

In a repository this standard governs, the total number of lines in Go
test files (`*_test.go`) MUST NOT exceed 3.0 times the total number of
lines in that repository's other Go files. A suite manifest MAY declare a
different ceiling as `constraints.max_test_to_product_lines`; where none
is declared the ceiling is 3.0.

Every line counts, blank lines and comments included, because a ratio
that first has to agree on which lines are real is a ratio nobody
computes. Only the repository's own code counts: files under a nested Go
module — any directory below the root carrying its own `go.mod` — under
`testdata/`, or under a vendored or tooling directory are material the
repository holds rather than code it maintains, and enter neither half.
Task fixtures are nested modules for exactly this reason.

The repository the check runs in is always measured. Where one project
governs several repositories, the others are named to the check through
the colon-separated `UZUSHIO_GOVERNED_REPOS` rather than found by their
place on somebody's disk, and each is held to the same ceiling.

The rule is about weight, not about coverage. A test suite three times
the size of its subject is not thorough, it is a second system with no
tests of its own; the failure this cites is one where nobody was ever
obliged to compute the number.
