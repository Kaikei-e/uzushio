# A held-out task does not run the standard's own toolchain

A task in the held-out split MUST NOT exercise the code of this standard's
own toolchain — uzushio, CMoA or DocDag. Concretely, a held-out task's
repository MUST resolve to a path under the task's own directory, and the
Go module it presents MUST NOT be one of those three. A task the split
names but whose manifest or module cannot be read fails the check: an
unanswerable question is not a passed one.

Dogfooding is cheap material and it is the wrong material for the split
that decides. When the harness and the subject are the same code, a
regression in one and a regression in the other arrive as one event, and
the held-out number — the only number a harness edit is accepted on — can
no longer say which happened. Held-in tasks may sit anywhere; this clause
binds the split that is used to decide.
