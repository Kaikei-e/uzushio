# A harness project retired with its core value never measured

An earlier project of the same author was retired after its core value
went unmeasured. Three failure modes bear on the rules that cite this
record.

**The upkeep outgrew the subject.** Test code accumulated far faster than
the code it tested, and it accumulated on the parts that were easy to
test. Nothing in the project ever compared the two quantities, so the
imbalance was never a fact anybody had to answer for; it was only ever an
impression, and impressions lose to the next green build.

**"Minimal" constrained shape, not amount.** The scope rule the project
kept was a rule about the shape of an artefact — what a change had to look
like — and none about how much one change was allowed to be. A single
change could therefore carry several milestones at once and still be
in-scope by its own standard, which made review a matter of reading the
diff rather than of checking a claim.

**The dogfooding target sat on the critical path.** The project measured
itself on itself. A regression in the harness and a regression in the
thing being measured were the same event, so the measurement could not
say which had happened, and the one number the project existed to produce
never became trustworthy enough to act on.

None of the three was a mistake anybody made on a given day. Each was a
quantity nobody was obliged to look at.
