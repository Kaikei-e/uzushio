# Check the test-to-product line ratio

Counts lines of `*_test.go` against lines of every other `.go` file and
fails when the ratio exceeds the ceiling. The repository the test runs in
is always measured; each colon-separated path in `UZUSHIO_GOVERNED_REPOS`
is measured as well, held to the same ceiling, and a path named there that
is not a directory fails rather than being passed over. Nested modules,
`testdata/`, `vendor/`, `node_modules/` and `.git` are walked past, and
only `.go` files are read at all, so the generated corpus fixtures under
`lint/` enter neither half. The ceiling comes from the suite manifest's
`constraints.max_test_to_product_lines` where the manifest declares one
and is 3.0 otherwise. Every measured ratio is printed whether the test
passes or not: the number is the point, and a number only shown when it is
bad is a number nobody watches move.
